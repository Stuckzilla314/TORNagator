## 2024-05-24 - DOM-based XSS via Webview src attribute
**Vulnerability:** The Electron `<webview>` component's `src` attribute was directly accepting user-provided input (via Custom Quick Actions and programmatic navigation requests) without validating the URL scheme. This permitted DOM-based XSS execution if a user entered `javascript:`, `data:`, or `vbscript:` schemes.
**Learning:** Even though `webSecurity` and `contextIsolation` exist, injecting a `javascript:` URI into a webview/iframe source bypasses them because the JS executes in the context of the loaded view. User input controlling the `src` attribute of webviews or iframes must always have its scheme verified and strictly limited to `http://` or `https://`.
**Prevention:** Created a centralized `sanitizeWebviewUrl` helper function that trims whitespace, normalizes to lowercase, strictly blocks `javascript:`, `data:`, and `vbscript:` schemes by defaulting to `about:blank`, and automatically prepends `https://` if an explicit secure scheme is missing. This sanitization is applied at both input boundaries (`handleSaveNewAction`, `navigateTo`, `requestedUrl` props) and at the final render boundary (`src={sanitizeWebviewUrl(url)}`).
